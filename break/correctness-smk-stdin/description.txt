Bug: write command ignores stdin — data written via stdin is not stored; read returns empty.

Spec: write must read plaintext from stdin and store it; subsequent read must return that data.
Root cause: stor.c:283-295 — the write action only checks for -i <infile> or a positional
  inline argument. There is no case for reading from stdin (fd 0). When the harness pipes
  content via stdin, the program ignores it and stores zero-length ciphertext.

Trigger: register, create file 'f', write 'hello' via stdin, read file 'f'.
Expected (oracle): fourth command exits 0 with stdout "hello".
Actual (bug): fourth command exits 0 with stdout "" (empty).
