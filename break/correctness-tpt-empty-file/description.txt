Bug: empty string filename is accepted by 'create' instead of being rejected
with exit 255.

Spec: -f requires a non-empty filename. On any invalid argument, stor must
print 'invalid' and exit 255.

Root cause: stor.c only checks strlen(file) > MAX_FILENAME_LEN (256), not
strlen(file) == 0, so an empty string passes validation and a file with an
empty name is created (exit 0, no output).

Trigger: register user then create with -f '' (empty string filename).
Expected (oracle): second command exits 255, stdout 'invalid'.
Actual (bug): exits 0, stdout ''.
