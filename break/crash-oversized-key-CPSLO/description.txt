NOT APPLICABLE to CPSLO (team 108).

For register: stor.c checks strlen(key) >= MAX_NAME (256) before use.
For write/read: the key is NOT length-checked but is passed directly to
PKCS5_PBKDF2_HMAC(key, strlen(key), ...) which handles arbitrary-length keys
without copying to any stack buffer. No overflow occurs.

There is no fixed-size stack buffer for the key argument in any code path.
This attack class requires teams that memcpy or strcpy the password into a
local char buf[N] before hashing. CPSLO does not do this.
