NOT APPLICABLE to CPSLO (team 108) via stdin.

CPSLO's stor.c does not read write content from stdin. Content comes from:
  (a) positional argv[optind+1]  -- allocated with malloc(strlen(content))
  (b) -i infile                  -- allocated with malloc(file_size)

Both paths use heap allocation (no fixed stack buffer). Passing 64 KB
as a positional argument results in malloc(65536) on the heap, which succeeds
without any memory corruption.

The stdin-based overflow attack applies to teams that do something like:
  char buf[BIG]; fgets(buf, sizeof(buf), stdin);
and then overflow it. CPSLO has no such path.

A large positional argument test is kept in the commands array as a
harmless sanity check, but it will not produce SIGSEGV or SIGABRT against
CPSLO's binary.
